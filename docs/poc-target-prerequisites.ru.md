# Требования к цели для PoC (operator SOP)

> 🇬🇧 English version: [poc-target-prerequisites.md](poc-target-prerequisites.md)

Что должно уже существовать в **аудируемом Foundry-проекте** (`POC_PROJECT`), прежде чем
`scripts/poc_queue_runner.py` сможет с пользой драфтить и (опционально) fork-верифицировать PoC.

Это **target-side** настройка. Быстрый старт агента (`.env`, Ollama, Langfuse) её не покрывает.
Ничего таргет-специфичного в это репо не коммитится.

Контекст флоу: [diagrams/poc-writing-flow.ru.md](diagrams/poc-writing-flow.ru.md).

---

## Ментальная модель

```
У цели уже есть tracked Deploy/Setup-база
  → раннер наследует её; может синтезировать расширение, если нужного типа нет
У цели нет пригодного deploy-харнесса
  → оператор пишет/указывает скаффолд; иначе жди base-insufficient
```

Раннер построен, чтобы **наследовать реальную deploy-инфраструктуру проекта**, а не бутстрапить
полный стек протокола из пустого дерева `test/`.

---

## Что раннер ожидает от цели

### 1. Корень Foundry-проекта

- `foundry.toml` (учти `test = ...`, если не дефолт)
- Зависимости резолвятся офлайн в sandbox (`lib/`, `node_modules/`, remappings)
- Solidity-исходники для контрактов в скоупе

### 2. Deploy / PoC-скаффолд (обязателен)

**Tracked** (git-оригинал) тест-база, которую модель наследует — обычно с именем вроде
`*Base`, `*Setup`, `*Deploy`, `*Harness` или `*Fixture`.

| Источник | Как |
|----------|-----|
| Авто-обнаружение | Самая наследуемая подходящая база под Foundry-`test`-директорией (только git-tracked) |
| Переопределение оператором | `--test-scaffold path[,path...]` или env `POC_SCAFFOLD` |
| Отключено | `--no-scaffold` (только для намеренных абляций; жди слабых результатов) |

Достаточная база обычно проводит: access control / роли, CDO (или vault-стек), accounting,
strategy + cooldowns, которые нужны сьюту, и хелперы для сидинга депозитов.

**Анти-паттерн:** не коммить skill-сгенерированные или answer-PoC как скаффолд. Авто-обнаружение
игнорирует untracked-файлы, чтобы модели не давали решение; tracked-«answer»-базы ломают
эксперимент.

### 3. Покрытие скаффолдом под конкретную находку

Если тип целевого контракта находки **не** декларирован/задеплоен на резолвнутой базе (например,
база деплоит CDO-стек, но не `SharesCooldown`), `scaffold_missing_types` **гейтит** находку —
драфт на заведомо недостаточной базе **запрещён** (это не мягкий диагностик). Тогда харнесс:

1. Пробует **синтезировать базу-расширение**, которая `is ExistingBase` и деплоит недостающие
   тип(ы) (feature 011); если эта база компилируется, драфт продолжается на ней.
2. Иначе маршрутизирует к терминалу — и два терминала **учитываются по-разному**:

| Терминал | Nature | Считается в модельном рейте? | Когда |
|----------|--------|------------------------------|-------|
| `base-insufficient` | `harness-infra` | **Нет — исключён** (разрыв окружения) | маршрут lookup не смог запуститься (нет symbol index / lookup budget 0), **либо** deploy-база вообще не резолвится (спека 001) |
| `lookup_failed` | `model` | **Да — остаётся** в знаменателе | маршрут lookup **запустился** (индекс сверен по каждому недостающему типу) и пригодного деплоя не нашлось — настоящий промах модели, никогда не переклеивается в infra |

**Не** считай их взаимозаменяемыми: `base-insufficient` — окружение и покидает знаменатель
модели; `lookup_failed` — промах модельной колонки и остаётся в нём. Смешение раздувает измеренный
рейт способности.

**Отсутствующая база (спека 001).** Когда *никакая* deploy-база не резолвится для находки, а
скаффолдинг **не** был намеренно отключён (`--no-scaffold`), раннер делает short-circuit в
`base-insufficient` (окружение) *до* гейта недостающих типов — он **не** молча драфтит на промпте
«база не предоставлена» и не заряжает провал модели. Агент **не** выдумывает полный протокол-харнесс,
когда существующей базы нет.

### 4. Fork / RPC (для зелёного `forge test`, не для пути A)

Многие contest-PoC зовут `vm.createFork` / `vm.envString("MAINNET_RPC_URL")` и нуждаются в
**archive** mainnet RPC на запиненном блоке.

| Исход | Значение |
|-------|----------|
| `compiled` (путь A) | Собирается + структурно реален под sandbox `--network none` / офлайн — дефолтная планка успеха |
| `passed` | Зелёный `forge test` (нужен fork + RPC, когда PoC fork-based; `--require-pass` / `--fork`) |

Без `MAINNET_RPC_URL` (или эквивалента, переданного в fork-путь раннера) fork-PoC падают на
`setUp`. Это инфра, а не плохое извлечение находки.

Правила bounty / сидинга (например, транши засеяны ≥ N ассетов) живут в доках программы на
**цели**; PoC должны их уважать, если отчёт/программа этого требует.

## Чеклист оператора (перед `poc_queue_runner`)

1. [ ] `POC_PROJECT` указывает на корень Foundry; `POC_REPORT` — на аудит-отчёт.
2. [ ] Цель собирается локально (`forge build` / известный CI-образ).
3. [ ] Tracked deploy-база существует **или** задан `--test-scaffold` / `POC_SCAFFOLD`. Если задал —
      путь должен резолвиться в файл; опечатка pre-flight-абортит весь прогон (спека 001 FR-011),
      она **не** игнорируется молча.
4. [ ] Эта база (или известный synth-путь) может достать контракты, которые нужны находкам; если
      нет — расширь базу на цели или прими synth / `base-insufficient`.
5. [ ] Для fork PASS: archive `MAINNET_RPC_URL` доступен раннеру/sandbox fork-пути; запиненные
      блоки в тестах существуют на этом RPC.
6. [ ] Хватает памяти хоста для холодных `via_ir`-сборок, если цель их использует (OOM ≠ промах модели).
7. [ ] Не сидь grounding готовыми exploit-PoC для тех же находок.

## Что агент может и чего не может

| Может | Не может |
|-------|----------|
| Авто-найти или использовать операторский скаффолд | Бутстрапить полный стек без deploy-базы |
| Гейтить по недостающим типам (запрет драфта на недостаточной базе) | Гарантировать правильный вариант strategy (напр. Neutrl vs Midas) без правильной базы |
| Синтезировать инкрементальную базу-расширение | Превратить path-A `compiled` в fork `passed` без RPC/сети |
| Пометить отсутствующую/недостаточную базу как окружение (`base-insufficient`, harness-infra) | Молча принять опечатку в `--test-scaffold` (она pre-flight-абортит) или зарядить отсутствующую базу модели |
| Держать настоящий промах модели (`lookup_failed`) в знаменателе модели | Заменить операторское суждение о bounty/сидинге |

## Спросить vs сгенерировать — что раннер делает с недостающим входом

Раннер — **неинтерактивный батч-процесс**. Он никогда не паузится посреди прогона, чтобы
запросить конкретный недостающий файл: требования удовлетворяются **заранее** (этот SOP), а
блокеры всего прогона всплывают как **pre-flight-аборты**, не как per-finding-запросы.

| Недостающий вход | Что происходит |
|------------------|----------------|
| Операторский скаффолд задан, но не резолвится (опечатка) | **Pre-flight-аборт** (`exit 2`, называет путь) — спека 001 FR-011 |
| Fork RPC (`--fork` без `MAINNET_RPC_URL`) | **Pre-flight-аборт** |
| Хост модели упал (Ollama не поднят) | **Pre-flight-аборт** (прогрев проваливается) |
| Deploy-базы нет вообще (не `--no-scaffold`) | Per-finding **`base-insufficient`** (окружение; исключено из модельного рейта) |
| Нужного контракт-**типа** нет на существующей базе | **Сгенерировать**: синтез базы-расширения (feature 011); иначе `base-insufficient` / `lookup_failed` по §3 |
| Намеренная абляция `--no-scaffold` | Драфтит на «база не предоставлена»; исходы **остаются в модельной колонке** (измерение сырой способности) |

Из этого следуют две границы честности:

- **«Спросить» — заранее, не интерактивно.** Нет рантайм-канала, чтобы агент запросил файл; если
  требование не выполнено, оператор чинит и перезапускает.
- **«Сгенерировать» заполняет только частичный разрыв.** Синтез расширяет *существующую* базу,
  добавляя недостающий тип — он никогда не фабрикует базу там, где ничего не резолвится.
  Отсутствующая база — это разрыв окружения, а не то, что модель должна выдумать.
